# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Patch Notes Delivered (PND) is a World of Warcraft addon (Lua) that shows official game patch notes and addon changes on login. There is no build step — the addon is plain Lua loaded by the WoW client via the `.toc` file. The repo also contains a Python-based GitHub Actions pipeline that scrapes Blizzard news and uses an LLM (Gemini) to draft patch-notes updates as a PR.

## Repository layout

- `PatchNotesDelivered/PatchNotesDelivered.toc` — addon manifest (interface versions, addon version, load order of libs/notes/core files). Any new Lua file must be added here or it won't load.
- `PatchNotesDelivered/PatchNotesDelivered.lua` — core addon logic: AceAddon init, minimap/data-broker button, options menu, the patch-notes window (`ShowPatchNotes`), slash commands (`/pnd`, `/pnd-mini`).
- `PatchNotesDelivered/PatchNotesWindow.lua` — custom AceGUI container widget (`Window-PND`) that `ShowPatchNotes`/`ShowPatchNotesPopup` build their windows from. Wraps Blizzard's native `ButtonFrameTemplate` (portrait, title, close button, inset content area all supplied by the template) rather than drawing custom chrome; addon-specific glue code, not a vendored library.
- `PatchNotesDelivered/PatchNotesText.lua` — `AVAILABLE_NOTES` registry mapping version strings to the per-version note tables in `notes/`, plus `BuildPatchNotes()` which flattens the currently selected note into `PatchNotesDelivered_Text` for display.
- `PatchNotesDelivered/notes/patch-*.lua` — one file per game patch version, each exporting a `PatchNotesDelivered_Notes_<version>` global table with fields like `version`, `build`, `hotfix`, `gameChangesHotfixes`, `gameChangesPatch`, and one `<class>ChangesPatch` field per WoW class. New patches get a new file here (added to both the `.toc` and `AVAILABLE_NOTES`), not by rewriting old ones.
- `PatchNotesDelivered/libs/` — vendored third-party Lua libs (Ace3, LibDataBroker-1.1, LibDBIcon-1.0), each a git submodule except the plain-vendored `Ace3` (see `.gitmodules`); don't hand-edit vendored libs. Also contains `libs/wow-ui-source` — a **dev-only** submodule mirroring Blizzard's client FrameXML/SharedXML source, used to look up exact frame-template field names (e.g. `PortraitFrameTemplate`/`ButtonFrameTemplate` internals) when building UI against Blizzard's shared templates. It is intentionally excluded from the `.toc` and never loads in-game.
- `Changelog.md` — Keep-a-Changelog-style log. Versioning is `A.B.C`: **A** = major feature bump, **B** = tracks WoW's major game version (e.g. `12` in `12.0.0`), **C** = increments on every release (hotfix/patch/minor). Update this alongside version bumps.
- `.github/scripts/` — Python automation (scraping + LLM formatting), not part of the addon runtime.
- `.github/workflows/` — the release/automation pipeline (see below).

## The automation pipeline (`.github/`)

This is the non-obvious part of the repo — most day-to-day changes to `notes/*.lua` are generated by this pipeline rather than hand-written:

1. **`run-update-agent.yml`** (manual, or intended daily cron — currently commented out): checks out `dev`, runs `scrape_news.py <url>` to pull a Blizzard news article, then `update_patch_notes_agent.py` sends the scraped text + existing note sections to Gemini (`GOOGLE_API_KEY`), which returns only the *new* hotfix/patch entries (filtered to current retail — "The War Within" — discarding Classic/SoD/Hardcore content). The script prepends the new entries, bumps the `.toc` iteration version, and opens a PR into `dev` (`updates/auto-patch-notes-v<version>`).
2. **`scrape-news.yml`**: standalone scraper run, pushes raw scraped JSON/text to a timestamped branch under `.github/data/` for inspection without touching notes.
3. **`create-release.yml`** (manual): run from `main`; reads the version from the `.toc`, extracts the matching `Changelog.md` section, zips `PatchNotesDelivered/`, tags `vA.B.C`, and creates a GitHub Release.
4. **`publish-release.yml`** (manual): downloads the latest GitHub Release asset and uploads it to CurseForge and Wago/WowUp, using the version parsed out of a specific notes file (`vars.NOTES_FILE`).
5. **`check-curseforge-game-version.yml`** (manual): looks up a CurseForge game-version ID for a given patch string — useful before wiring a new WoW version into publishing.
6. **`promote-issue-to-bug.yml` / `promote-issue-to-feature.yml`**: when an allow-listed user (`vars.APPROVED_USERS`) applies the `approved` label to an issue also labeled `bug`/`feature`, a branch (`bugs/bug-...` / `features/feature-...`) is created off `dev`.

Branching model: `dev` is the integration branch (auto-update PRs and issue-promotion branches target it); `main` is release-only (tags and packages are cut from it).

## Common tasks

- **Add a new patch's notes**: create `notes/patch-X.Y.Z.lua` following the existing field structure (see any file in `notes/` as a template — note the `140`-char line-length convention marked in the file headers, matching `.vscode/settings.json`'s `editor.rulers`), add it to the `# Notes Files` list in the `.toc`, and add an entry to `AVAILABLE_NOTES` in `PatchNotesText.lua` (newest first).
- **Run the update agent locally**: `python .github/scripts/update_patch_notes_agent.py <scraped_text_file> <notes_file>` (requires `GOOGLE_API_KEY`). Get scraped input first via `python .github/scripts/scrape_news.py <url>`.
- **Bump the addon version manually**: edit `## Version:` in `PatchNotesDelivered.toc`; add a matching `## [A.B.C]` entry to `Changelog.md`.
- There is no linter/test/build command in this repo — validation is manual (load the addon in-game) or via the Lua Language Server config in `.vscode/settings.json` (Lua 5.1 runtime, WoW API annotations from the `ketho.wow-api` extension).
- **Look up a Blizzard shared frame template's internals** (e.g. what fields/mixins `ButtonFrameTemplate` exposes): grep `PatchNotesDelivered/libs/wow-ui-source/Interface/AddOns/Blizzard_SharedXML*` — the `ketho.wow-api` extension only annotates global API functions, not template XML structure.

## Conventions

- Lua files start with a header comment block (addon name, author, file, description, license) — follow this for new files.
- Function doc comments use `--- Description:`, `--- @param:`, `--- @return:` above each function.
- Keep line length within 140 columns (see `.vscode/settings.json` rulers and the note files' explicit `Max note length` marker comments).
